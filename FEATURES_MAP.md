# Feature map

## Scope and reading guide

- Active product: [GJH Virtual Mall v11](https://yapweijun1996.github.io/Webpage-Design-Gallery/demos/corporate/gjh/v11/), an independent, unofficial concept, not evidence of tenancy, endorsement, stock or brand rights (`demos/corporate/gjh/v11/index.html`, `task.md`).
- The mall is the first district and proving ground for the **Modular 3D World Engine**, a Three.js-based framework intended to reuse movement, interaction, collision and eventually streamed districts (`goal.md`).
- Phases from `goal.md`: **P0** mall visual quality and shop-by-shop acceptance; **P1** multi-floor mall, enterable shops, seats and doors; **P2** engine extraction and district streaming; **P3** Singapore districts; **P4** Malaysia districts. These are goals, not completed-release claims.
- Unless stated otherwise, paths in the tables below are relative to `demos/corporate/gjh/v11/`; test paths are relative to the repository root. Status describes this checkout, not the live site or another branch. **Implemented** means code exists, not that device or design acceptance passed; **Partial** means the stated target is incomplete; **Planned** means a goal without a verified implementation. Historical review documents can describe superseded layouts.

## User journeys

1. **First visit:** directory/loading remains available during startup; after scene readiness, a compact Getting Started card teaches movement, look and interaction without pausing the scene. Skip or completion is remembered per browser viewer when local storage is available; Guide replays it. Failed WebGL/WASM leaves the directory (`assets/ui.js`, `assets/ux-tutorial.js`).
2. **Walk and run:** `player.js` maps WASD/arrows and Shift to Rapier capsule motion; Q/E turns, drag changes camera; `character-v2.js` animates the visitor and `world.js` provides colliders. `modes.js` pauses movement for overlays.
3. **Enter a shop:** approach an open-store door; in expanded mode use the contextual Open action, then walk through; in classic mode proximity opens it. Closed planned spaces remain blocked (`world.js`, `script.js`, `ui.js`).
4. **Inspect and add:** approach a New Moon shelf and use F/touch Inspect, or choose a directory product; shelf/product UI opens the details. Optionally rotate the unofficial preview, then Add to demo bag. `demo-bag.js` updates tab-scoped quantities; the external eShop is separate (`products.js`, `shelf-focus.js`, `ui.js`, `newmoon-detail-preview.js`, `demo-bag.js`).
5. **Sit:** approach a registered seat from its valid side and use the action; registry selects it, player checks the route and animates sitting. Stand uses a checked exit. Cart and held physical products constrain the action (`interaction-registry.js`, `seat-placements.js`, `player.js`).
6. **Open a door:** nearest `open` interaction dispatches to the selected door; `world.js` advances glass meshes and kinematic bodies together. Decorative planned-space doors have no such action (`interaction-registry.js`, `script.js`, `world.js`).
7. **Take a lift:** in expanded v2, return a held shelf item and stow the cart, approach the lift, Call if needed, then Ride. `elevator-v2.js` moves between ground and the upper deck; interruptions have recovery guards (`ui.js`, `player.js`, `lift-layout.js`).
8. **Use map:** open Map, choose an available store and close it; shared spatial anchors drive teleport. Planned lots are informational and unavailable (`ui.js`, `spatial.js`, `expanded-layout.js`).
9. **Customize:** open the visitor controls and select hair, outfit, skin or accessories; `visitor-v2-customization.js` updates the v2 model for this visit only (`visitor-v2-controls.js`, `character-v2.js`).
10. **Mobile:** use the first touch for a floating movement stick and a second for camera look; Run and contextual action invoke the same player/registry behavior. HUD/map/bag and overlays use `ui.js`, `style.css` and `modes.js`; real-device acceptance is pending (`task.md`).
11. **Offline and reconnect:** after worker installation, failed navigation serves cached `offline.html`; reconnect and retry to fetch the actual mall. The demo bag can survive a same-tab update when session storage is available, but neither mall nor catalog is precached (`pwa.js`, `pwa-sw.js`, `tests/browser_gjh_pwa.py`).

## Build, tests and deployment

- `python scripts/build_gallery.py` validates metadata and generates gallery HTML, `data/designs.json`, `version.json`, `sw.js` and v11 worker/runtime artifacts; `python scripts/build_gallery.py --check` checks synchronization. Do not edit generated files (`README.md`, `scripts/build_gallery.py`).
- `scripts/build_gjh_startup_js.py` and `data/gjh-startup-bundles.json` own generated `script.bundle.js`, `world.bundle.js`, `player.bundle.js`, `character-v2.bundle.js`. Clean checks require Python; rebuilding changed bundle inputs requires standalone Bun 1.3.11. `build_gjh_css.py`, `build_gjh_startup_pack.py`, `build_rapier.py` own combined CSS, asset pack and Rapier JS/WASM split (`README.md`).
- `python scripts/check_ssot.py` checks generated design-system artifacts and CSS debt, not Markdown. Neither it nor gallery `--check` covers this feature map (`scripts/check_ssot.py`, `scripts/build_gallery.py`).
- CI commands: `python -m unittest discover -s tests -p 'test_*.py' -v`; `node --test tests/gjh_*.test.mjs`. Focused runtime: `python tests/browser_gjh_v11.py` and feature-specific browser tests above; Playwright/Chrome are required (`README.md`). Browser suites are not run by the Pages workflow.
- The single-scene draw-call cap is **200** (`goal.md`); `tests/browser_gjh_interior_pilot_performance.py` asserts the budget in its tested scenarios, and `docs/gjh-v11-engine-interactions.md` records open-door checks. This is not proof of physical-device performance.
- `.github/workflows/pages.yml` runs SSOT, Python and Node tests, generated check, then `python scripts/build_gallery.py --output _site` and deploys Pages on `main` push or manual dispatch. `goal.md` says no GitHub Actions; the checked-in workflow exists, so that constraint and actual deploy configuration conflict. ## How to add a feature

1. Check `goal.md`, `task.md` and the current source, not just historical stage reports; choose the relevant feature row and preserve the directory/failure path.
2. For a world object, update its placement/data in `assets/world.js` or the relevant layout/asset module. For a seat or door, follow the anchors, availability and collision procedure in `docs/gjh-v11-engine-interactions.md`; reuse the registry rather than duplicating interaction logic.
3. For products or UI, update verified records in `index.html`/`assets/products.js` and existing `ui.js`/mode flows; preserve disclosures, keyboard/touch and session-only bag semantics.
4. For local models, record upstream ID, source, hashes and rights in the applicable `assets/*source*.json` or metadata; validate fallback, collision and 200-call scenarios. Do not assume draft inventory is licensed.
5. Change sources, regenerate affected artifacts, run the narrow Node/Python/browser checks plus applicable repository gates, and update relevant docs. Review real 390/768/1440 screenshots for visual work; simulated tests do not replace physical-device acceptance (`README.md`, `goal.md`).
