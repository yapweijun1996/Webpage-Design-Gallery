# V11 stage 9 — mall theme infrastructure

Status at the stage 9 snapshot: local implementation in the opt-in expanded preview, with **Everyday** as the only theme. Stage 10 subsequently added [Lunar New Year](gjh-v11-stage10-lunar-new-year.md), [Christmas](gjh-v11-stage10-christmas.md) and [Deepavali](gjh-v11-stage10-deepavali.md).

## Visitor experience

Visitors can open **Theme** in the 3D scene or **Mall theme settings** in the expanded store directory. The native dialog names the current selection, exposes a keyboard-operable select and Apply action, announces its result and returns focus to its opener. A modal theme panel pauses movement without stowing a cart, standing a seated visitor, dropping a physical product, losing a demo-bag selection or resetting an elevator journey. The original layout does not expose an unsupported theme setting. The expanded V1 visitor can use Everyday, although its existing lift limitation is unchanged.

The choice uses the browser-local key `gjh-v11-mall-theme-v1`, separate from the onboarding UI's light/dark appearance and language preferences. A valid choice is restored when the app starts; unsupported stored IDs fall back to Everyday and are replaced on the next successful Apply. If storage is unavailable, the selection continues in memory and the panel explains that it is session-only. There is no account, remote settings service, shared operator configuration, or live cross-tab synchronization. The panel currently uses English.

## Theme ownership and lifecycle

[The local theme registry and coordinator](../demos/corporate/gjh/v11/assets/mall-themes.js) own the selected ID, allowed definitions, status and persistence. User-controlled storage never supplies scripts, URLs or materials. The Everyday definition owns named scene roles for stone, wood, green, ivory, brass, glass and light colors, plus corresponding expanded-lift materials. [The scene adapter](../demos/corporate/gjh/v11/assets/world.js) validates its roles before applying them; the lift has its own validated adapter. Brand images, pinned GLB materials, interactions, geometry and collision are outside this initial color owner.

Preparation is separated from synchronous commit. A generation token and `AbortSignal` reject stale work; a failed preparation or commit keeps the previous active state, with the scene adapter attempting rollback. Staged resources provide a cleanup callback and are released on replacement, cancellation or destruction. Closing settings, hiding the document or losing WebGL cancels pending preparation. On actual graphics recovery, the current definition is reapplied before the renderer is declared ready. Reapplying Everyday updates the existing materials/lights without making another scene, texture or set of listeners.

At the stage 9 snapshot there were no themed decoration assets to load or replace; the alternative themes used in its coordinator tests were synthetic test records only. Stage 10 implements and tests its first real pack separately.

If the optional theme module cannot load, the stage 8 Everyday appearance and the mall remain available; the settings panel reports that theme settings are unavailable. During graphics loss the theme panel closes, settings are unavailable in the fallback directory, and the existing graphics recovery path controls re-entry. A no-JavaScript directory remains readable without a misleading settings button.

## Verification and limitations

The final candidate passed [theme coordinator and layout Node tests](evidence/gjh-stage9-20261115/theme-node.log), [theme browser acceptance](evidence/gjh-stage9-20261115/theme-browser.log), [V11 mode lifecycle](evidence/gjh-stage9-20261115/modes.log) ([results](evidence/gjh-stage9-20261115/modes.json)), [material and fallback checks](evidence/gjh-stage9-20261115/materials.log), [expanded PWA](evidence/gjh-stage9-20261115/gjh-pwa.log), [generator](evidence/gjh-stage9-20261115/generator.log), [design generator](evidence/gjh-stage9-20261115/design.log) and [SSOT](evidence/gjh-stage9-20261115/ssot.log). The browser checks cover 320, 390, 768, 844 landscape and 1440 px; keyboard focus wrapping and return; eight repeated applications without scene/resource growth; active cart, seat, carried product, lift and bag; unknown saved values; blocked storage; missing theme module; actual WebGL loss and restoration; Visitor V1; and the original/no-JavaScript directory. The Node tests use synthetic alternatives to exercise staged selection, a remembered choice, aborted and stale preparations, failure, cleanup and validated color/light roles. They do not demonstrate a real seasonal-theme transition.

The broader suite also passed [49 Python tests](evidence/gjh-stage9-20261115/units.log), [gallery browser](evidence/gjh-stage9-20261115/gallery.log), [28 older GJH demo cases](evidence/gjh-stage9-20261115/demos.log), [gallery PWA](evidence/gjh-stage9-20261115/pwa.log), [expanded lift](evidence/gjh-stage9-20261115/lift.log), [shell and cart](evidence/gjh-stage9-20261115/shell.log), [three existing stores](evidence/gjh-stage9-20261115/stores.log) and [atrium/seats](evidence/gjh-stage9-20261115/atrium.log). That broader snapshot preceded the final addition of synchronous pending-selection cancellation on dialog close/Escape; the final theme, mode, materials, expanded-PWA and generator checks above were rerun after that addition. The older-demo suite did not receive an axe bundle, so its zero axe count is not an accessibility audit.

Actual screenshots show the theme panel at [390 px](evidence/gjh-stage9-20261115/settings-390.png), [844 px landscape](evidence/gjh-stage9-20261115/settings-844.png) and [1440 px](evidence/gjh-stage9-20261115/settings-1440.png), plus the [directory entry](evidence/gjh-stage9-20261115/directory-390.png). Browser emulation and synthetic alternate-theme tests are not physical-device, Safari, screen-reader or real seasonal-pack certification.
