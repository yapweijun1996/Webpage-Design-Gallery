# GJH V11 mall upgrade: stage 0 baseline

Date: 15 November 2026 (Asia/Singapore)
Status: **baseline captured and documented; existing findings remain open**. This is a snapshot of the current three-store demo, not the planned 17-store upgrade. No mall runtime code was changed for this baseline.

**Later follow-up:** F1, F2 and F4 were addressed and retested in the [stage 0 fixes report](gjh-v11-stage0-fixes.md). The observations below preserve the original baseline; F3 remains part of the planned redesign.

## Source and environment

The working tree contained staged/unstaged or untracked work from other tasks; it was copied without `.git` into an isolated temporary directory for testing. The underlying HEAD was `ffa2e4ec3f9e81c0c3a3f8efc269e2a3781076aa`, but the tested source **included uncommitted changes** and must not be described as that clean commit. During testing, other work changed the camera and later the directory. A final snapshot was taken after those changes; its 121 V11 files had no differences from the corresponding working-tree files at the final comparison. Later changes may invalidate this comparison.

The final V11 tree digest is `8bbbd530e9bd0408d1ccceae4465c40cf251f66308f75eae0b80976ed17feaf9`, computed over sorted relative paths, a NUL byte and each file's binary SHA-256. [Source manifest](evidence/gjh-stage0-20261115/latest/source-manifest.json) lists 142 checked runtime/shared/test files. For a durable direct-mall baseline, the [runtime source archive](evidence/gjh-stage0-20261115/latest/runtime-source-snapshot.tar.gz) contains the captured V11 files, shared assets, onboarding resources, runtime source and tests. Its SHA-256 is `372f50855ba4e755788d7f8358e50dbe0422f3eee726a6a0d6b0dd87089e2325`; all 142 manifest entries were checked against archive bytes. For public release the archive was repacked without macOS metadata; file bytes were reverified against the manifest. It is a **partial** source snapshot, not a full repository or deployable gallery build; full gallery rebuilds require the other demo sources. The archive includes the earlier uncommitted demo snapshot; its paths, file types and manifest hashes were reviewed before publication.

The final capture used real headless Chrome 157.0.8103.51, Apple M4, macOS 27.2, requested ANGLE Metal, Python 3.15.0 and Playwright 1.65.2. WebGL reported `ANGLE Metal Renderer: Apple M4`. Chrome DevTools independently loaded the isolated local URL and showed the 3D scene ready with no console errors/warnings in that inspected state. The browser contexts used DPR 2 and emulated touch below 1000 CSS px; they are not physical phone/tablet tests. Direct-capture service workers were blocked, and the site was served from localhost. Existing gallery, legacy-demo and PWA suites ran in another isolated copy so their screenshot-writing behavior could not overwrite the working tree.

The [recorded capture script](evidence/gjh-stage0-20261115/latest/capture-v2-used.py) contains the exact local port and temporary output path used. To repeat it, extract the archive into a separate directory, serve it on `127.0.0.1:8772`, adapt its output path to a new empty temporary directory, and use the stated Chrome/Playwright environment. The captured scripts use test hooks such as `__mall.teleport` and `__mall.step`; they are not proof of real touch or real user navigation. Archive-based direct captures do not replace the full generated-gallery test.

**F1 — 320px header clipping.** At 320×568 the `Store directory` button extends from x=229.94 to x=341.86, approximately 21.86 CSS px beyond the viewport. `documentElement.scrollWidth` is still 320, so a page-overflow check alone misses it. At 390px the right edge is 374, inside the viewport. A preceding-snapshot 320px action check still opened the directory; this finding is visual clipping, not proof that the action is completely unusable. [Bounds](evidence/gjh-stage0-20261115/latest/header-bounds.json). Recheck the full button, focus indicator and touch target on a future candidate.

**F2 — Scripted seat approach obstructed.** The final V2 mode test's route to (-5.7, 8.3) stopped near (-5.700, 11.065), where the kiosk is the nearby target. The source places its collider at (-5.3, 10.4), size 0.96 × 2.05 × 0.68 m; the test's straight approach intersects that region. A separate actual-scene diagnostic reproduced the old route stopping near the kiosk and then reached `courtyard-seat` by a different route, sat and stood. This supports a route/fixture conflict; it does **not** prove the seat is inaccessible, nor does it excuse the failing suite. Resolve the route and its acceptance against the future layout without weakening collision assertions. [Failure](evidence/gjh-stage0-20261115/latest/v2-modes-failure.txt), [alternate-route screenshot](evidence/gjh-stage0-20261115/latest/screens/seat-scripted-route-390.png).

**F3 — Existing visual direction.** In the [desktop arrival](evidence/gjh-stage0-20261115/latest/screens/atrium-v2-1440.png), the elevator panel occludes much of the right-hand storefront view and the central gold ring remains present. The current elevator is an open prototype rather than a realistic integrated cabin, and the storefronts/furnishings do not yet match the owner-selected interior direction. These are visual/design observations, not a claim that the lift fails to operate.

**F4 — Synthetic gamepad path is unstable across snapshots.** Two unmodified earlier-snapshot onboarding runs timed out waiting for `nearby === 'mili'`; an instrumented run and one unmodified final-snapshot run passed. Source and timing both differed between runs. Root cause is unknown; do not treat the final pass as proof the earlier failures were fixed. Retain this as a regression to investigate before claiming stable gamepad onboarding.

## Local performance observations

One final-snapshot capture per viewport; fixed arrival view, DPR 2, locally served source, Auto quality, real headless Chrome / ANGLE Metal on Apple M4. Counters are sampled after scene startup; 120 requestAnimationFrame interval samples describe browser scheduling, not GPU frame time, physical-device FPS or field performance. Other applications/browser activity was not controlled. The observed readiness time was polled after DOMContentLoaded, was not repeated under controlled load, and is retained only in the raw data rather than used as a target.

| 1440×900 | Detailed / 2 | 196 | 313,370 | 113 / 29 | 16.7 / 16.8 |
| 768×1024 | Balanced / 2 | 174 | 312,238 | 106 / 24 | 16.7 / 16.7 |
| 639×826 | Balanced / 2 | 176 | 313,230 | 108 / 24 | 16.7 / 16.8 |
| 390×844 | Balanced / 1.25 | 158 | 310,358 | 104 / 19 | 16.7 / 16.7 |
| 320×568 | Balanced / 1.25 | 172 | 311,714 | 106 / 24 | 16.7 / 16.7 |

For each isolated startup capture, the browser resource timing list contained 75 entries and 10,544,519 reported transfer bytes (~10.06 MiB). This is a local browser measurement, not a production network transfer or mobile bandwidth guarantee. No page errors, console errors/warnings or failed requests were recorded in those five capture sessions. The 1440px V2 arrival sample is close to the existing 200-call test limit; one entry view does not prove the full V2 route stays under that limit. The legacy V1 full test's observed maximum was 193 calls on 1440px, 173 on 768px and 158 on 390px.

## Limits and next-stage use

This baseline identifies the source, evidence, test conditions and outstanding issues, rather than declaring the mall fully accepted. No physical phones, tablets, gamepad, Safari, screen reader, field performance or real safe-area behavior were tested. The full V2 mode suite and two earlier gamepad runs did not pass; additional 17-store, theme switching and redesigned-scene coverage does not exist yet. Treat the final source archive and measurements as the comparison point for future slices; rebaseline if source changes. The [upgrade master plan](gjh-v11-mall-upgrade-master-plan.md) and [task.md](../task.md#expanded-17-store-upgrade--2026-11-15) retain the remaining work and findings.
