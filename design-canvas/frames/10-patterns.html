Pattern notes

Hero

Anatomy. Context label, benefit headline, supporting copy, action group.

Variants. One primary action or a primary and secondary pair, shown above.

Do. Name the destination in each link. Don’t. Give both links primary styling.

--dc-surface-2 --dc-text-2xl --dc-space-6

Feature grid

Anatomy. Section heading and a list of title–description pairs.

Variants. Three columns or one stacked list at narrow widths. Static cards have a default state.

Do. Describe what people can accomplish. Don’t. Style static cards as links.

--dc-surface --dc-line --dc-space-3 --dc-radius

Pricing and CTA

Anatomy. Plan name, price, billing unit, included features, action.

Variants. Inline CTA on wide screens and a stacked CTA on narrow screens.

Do. Put the billing unit beside the price. Don’t. Hide the unit behind the CTA.

--dc-text-xl --dc-surface-2 --dc-space-4

Footer

Anatomy. Product name and labeled navigation.

Variants. Inline links when space allows and wrapped links on narrow screens.

Do. Keep link names consistent with their destinations. Don’t. Repeat every page section.

--dc-line --dc-text-sm --dc-space-4 --dc-tap

Action states

Hero, pricing, and footer links start in their default state. Hover adds an underline, keyboard focus adds an outline, and pressing adds an inset border. Navigation links have no disabled or error state.

--dc-brand --dc-on-brand --dc-focus --dc-tap

Accessibility checklist

  • Follow a logical heading and keyboard order.
  • Tab through every link and confirm that focus remains visible.
  • Keep every tap target at least 44 × 44 CSS pixels.
  • Check text contrast in light and dark modes.
  • Check for horizontal overflow at 320px.
  • Respect reduced-motion preferences. These patterns use static state changes.

Do. Build each section around one job. Don’t. ask for the same decision in multiple sections.
