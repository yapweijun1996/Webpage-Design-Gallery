# SDS_SPEC: Swarm Design System v1 interface spec (binding for all workers)

Plan and rationale: `docs/swarm-design-system-plan.md`. This file fixes names and APIs so workers can code in parallel. Node 23, zero npm dependencies, CommonJS for Node tools, plain browser scripts (no modules, ES2019) for runtime files, English identifiers and comments. Repo root = cwd. All new files live under `swarm/design-system/` or `swarm/tools/` or `swarm/test/` as listed in each worker's assignment; never edit files you do not own.

## 2. tokens.json (SSOT) and generated CSS
Schema:
```json
{ "version": "1.0.0",
  "primitives": { "color": {"forest-900":"#101C16", ...}, "font": {...}, "size": {...} },
  "scale":   { "space": {"1":"4px","2":"8px","3":"12px","4":"16px","6":"24px","8":"32px","12":"48px","16":"64px"},
               "text": {"xs":"12px","sm":"14px","base":"16px","lg":"18px","xl":"24px","2xl":"32px","3xl":"48px","display":"clamp(40px, 9vw, 104px)"},
               "radius": {...}, "shadow": {...}, "z": {...}, "dur": {...}, "ease": {...}, "layout": {...}, "loader": {...} },
  "themes": { "light": {"color-bg":"{primitive path}", ...}, "dark": {...} },
  "brands": { "forest-gold": {"light": {...overrides}, "dark": {...overrides}}, "gjh-classic": {"light":{...},"dark":{...}} } }
```
Values may reference primitives as `{color.forest-900}`; `build.js` resolves them. Every CSS custom property is prefixed `--sds-`.

### 2.1 Semantic colour roles (every theme and brand must define ALL of them)
`--sds-color-bg`, `-surface`, `-surface-2`, `-surface-inverse`, `-text`, `-text-muted`, `-text-inverse`, `-on-action`, `-border`, `-border-strong`, `-action`, `-action-hover`, `-action-active`, `-accent`, `-focus`, `-success`, `-success-bg`, `-warning`, `-warning-bg`, `-danger`, `-danger-bg`, `-info`, `-info-bg`, `-scrim` (image overlay), `-scrim-strong`.
Contrast (computed in `sds-tokens.test.js`, fail the test below these): text on bg/surface/surface-2 >= 4.5; text-muted on bg/surface >= 4.5; on-action on action/action-hover/action-active >= 4.5; text-inverse on surface-inverse >= 4.5; focus on bg and on surface >= 3; border-strong on bg >= 3; status text on its -bg >= 4.5. Check every combination of theme (light, dark) x brand (none, forest-gold, gjh-classic).

### 2.2 Scales
Space `--sds-space-{1,2,3,4,6,8,12,16}`. Type `--sds-text-{xs,sm,base,lg,xl,2xl,3xl,display}`, `--sds-font-sans`, `--sds-font-mono`, `--sds-weight-{regular,medium,bold}`, `--sds-leading-{tight,body}`, `--sds-tracking-{tight,normal}`. Radius `--sds-radius-{sm,md,lg,pill}`. Shadow `--sds-shadow-{1,2}`. Z `--sds-z-{base,sticky,bar,overlay,modal,toast}`. Motion durations `--sds-dur-{instant,fast,base,slow,reveal}` = 0ms,120ms,220ms,400ms,600ms; easings `--sds-ease-{standard,emphasized,exit}`. Layout `--sds-container` (1200px), `--sds-gutter`, `--sds-tap` (44px), `--sds-header-h` (56px), `--sds-bar-h` (60px), `--sds-safe-{top,right,bottom,left}` = `env(safe-area-inset-*, 0px)`. Loader `--sds-loader-size`, `--sds-skeleton-base`, `--sds-skeleton-shine`.
`prefers-reduced-motion: reduce` must set every `--sds-dur-*` to `0.01ms`.

### 2.3 Theme selection (themes.css)
Default (no attribute) = light. `[data-theme="light"]`, `[data-theme="dark"]`, and `[data-theme="auto"]` (applies the dark block only inside `@media (prefers-color-scheme: dark)`). A brand layer `[data-brand="forest-gold"]` / `[data-brand="gjh-classic"]` overrides the semantic roles and comes AFTER the theme blocks, with separate light and dark values (`[data-brand="x"][data-theme="dark"]`, and the auto + media variant). `color-scheme` is set accordingly.
Brand anchors (workers may refine to pass contrast, never change the names): forest-gold dark: bg `#101C16`, surface `#192A20`, surface-2 `#24402F`, text ivory `#F4EFE4`, action gold `#D9A93A` hover `#C4932A`, on-action `#101C16`. If `swarm/projects/home/direction.md` exists, read its palette section and prefer those values. gjh-classic dark: bg `#0f1115`, surface `#171a21`, text `#f4efe4`, action red `#d9261c` hover `#b81f16`, on-action `#ffffff`. Provide light counterparts for both.

## 3. components.css (owner B)
Token-only (no colour, px font size, duration or easing literals except `0`, `1px` hairlines and `100%`). Every component supports keyboard focus (`:focus-visible` ring from `--sds-color-focus`), hover, active, disabled, and reduced motion. Class API (BEM-ish, `sds-` prefix):
`.sds-container`, `.sds-stack`, `.sds-cluster`, `.sds-visually-hidden`, `.sds-eyebrow`, `.sds-badge`,
`.sds-btn` (+ `--primary --secondary --ghost --danger --sm --lg`, `[aria-busy="true"]` spinner, `[disabled]`),
`.sds-chip` (+ `--selected`), `.sds-card`,
`.sds-nav` (sticky header bar, `__brand`, `__links`, `__menu` via details/summary),
`.sds-actionbar` (fixed bottom bar on phones, floating pill >= 48rem, safe-area aware, `--sds-bar-h`),
`.sds-chapter` (full-bleed image chapter: `__media` img, `__scrim`, `__body`, `__eyebrow`, `__title`, `__text`, `__actions`, `__caption`; min-height 100svh, one dominant image),
`.sds-rail` (scroll-snap horizontal rail, focusable, `__item`),
`.sds-field`, `.sds-radio-chip` (native radio + label), `.sds-disclosure` (details/summary FAQ),
`.sds-footer`, `.sds-prefs` (theme/brand/language control group, used by the shell),
`.sds-skeleton` (shimmer, no layout shift), `.sds-spinner`, `.sds-progress`, `.sds-toast`.
Reveal animation: attribute `data-reveal="fade|rise|scale"` with optional `data-reveal-delay="1|2|3|4"`; implemented in CSS with `@supports (animation-timeline: view())` and a fully visible fallback; the runtime adds `data-revealed` for browsers without it. Only `transform` and `opacity` animate.

## 4. runtime.js (owner C): `window.SDS`
```js
SDS.version                      // string
SDS.theme.get() / .set('light'|'dark'|'auto')     // persisted in localStorage key 'sds.theme', default 'auto'; sets <html data-theme>; updates <meta name="theme-color">
SDS.brand.get() / .set('none'|'forest-gold'|'gjh-classic')   // key 'sds.brand', default from <html data-default-brand> or 'none'; sets data-brand
SDS.lang.get() / .set('en'|'zh-Hans'|'ms')        // key 'sds.lang'; sets <html lang>; calls SDS.i18n.apply()
SDS.lang.list                    // ['en','zh-Hans','ms']
SDS.loader.show() / .hide()      // toggles <html data-loading>; hide() is also called after first paint + fonts/images above the fold or after 2500 ms
SDS.reveal.init()                // IntersectionObserver fallback adding data-revealed; no-op where animation-timeline is supported or reduced motion
SDS.on(name, fn) / SDS.off       // events: 'ready', 'themechange', 'brandchange', 'langchange'
SDS.update.check() / .apply()    // service worker update flow (section 6.3)
```
Declarative controls: any element with `data-sds-theme="dark"`, `data-sds-brand="forest-gold"` or `data-sds-lang="zh-Hans"` becomes a switch on click (sets `aria-pressed` on the active one; a `<select data-sds-select="lang|theme|brand">` also works).
All storage access wrapped in try/catch; the script must work with storage blocked. Guard iOS pinch zoom: `gesturestart` preventDefault with `{passive:false}` only when `<html data-viewport-lock>` is present. No globals other than `SDS`.
### 4.1 boot.js
Under 1.5 KB, no dependencies, designed to be inlined in `<head>`: reads the three storage keys, sets `data-theme`, `data-brand`, `lang` on `<html>` before first paint (avoids flash), sets `data-loading`.

## 5. i18n (owner D): `window.SDS.i18n` and tool
Markup contract: `data-i18n="<key>"` sets textContent from the catalog; the inline English text stays as the default and as the fallback. `data-i18n-attr="aria-label:key;title:key2;alt:key3"` for attributes. `data-i18n-vars='{"n":3}'` interpolates `{n}`. Plurals: catalog keys `key.one`, `key.other` (and `.zero`, `.two`, `.few`, `.many` when the language needs them) chosen with `Intl.PluralRules` and the `n` var.
Key convention: lowercase, dot separated, `[a-z0-9.-]+`, `<section>.<element>`, for example `hero.title`, `chapter.newmoon.cta`.
Catalog JSON: `{ "meta": {"lang":"zh-Hans","status":"machine-draft","generated":"ISO date"}, "messages": {"hero.title":"..."} }`. `en.json` has `"status":"source"`.
API: `SDS.i18n.load(lang) -> Promise`, `.apply(root=document)`, `.t(key, vars)`, `.format.number(n,opts)`, `.format.date(d,opts)`, `.format.currency(n, code='SGD')` using locales `en-SG`, `zh-Hans-SG`, `ms-MY` (same mapping as `src/preferences.js`). Catalogs are fetched from `i18n/<lang>.json` relative to the page; en is the source so loading en is a no-op restore of the inline text (store original text in a WeakMap like `src/preferences.js`). Missing key keeps the inline text and records it in `SDS.i18n.missing`. A MutationObserver re-applies for late-added nodes.
Tool: `node swarm/tools/i18n-extract.js <projectDir> [--write] [--check]` scans `sections/*.html` for `data-i18n*`, builds `en.json` from the inline text, lists keys missing in other catalogs, flags duplicate keys with different text, and with `--check` exits 1 if `en.json` is stale or any key is missing in any catalog. Also reports visible text nodes WITHOUT `data-i18n` (warn).
Chinese text must not rely on inline `<br>`; CJK uses `word-break: keep-all` plus `line-break: strict` through a `:lang(zh)` rule in components.css (owner B).

## 6. PWA shell and export (owner E)
### 6.1 index.html.tpl
Placeholders `{{TITLE}} {{LANG}} {{STYLES}} {{BODY}} {{SCRIPTS}} {{VERSION}}`. Must contain exactly `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover">`, `html{touch-action:manipulation}`, `<html data-viewport-lock>`, `<link rel="manifest" href="manifest.webmanifest">`, `<meta name="theme-color">`, apple-touch-icon, the inlined boot.js, a first-paint loader (`.sds-skeleton`/spinner visible until `SDS.loader.hide()`, CSS-only, no layout shift), the `.sds-prefs` control group (theme, brand, language), a version line and a "Check updates" button, and the update toast (`.sds-toast`: "Update available" + "Update now"; installs only after the click).
### 6.2 manifest and icons
`manifest.webmanifest`: name, short_name, `start_url` and `scope` relative (`./`), `display: standalone`, `theme_color`, `background_color`, icons 192, 512 and a maskable 512. Sub-path safe (works from a GitHub Pages sub-path).
### 6.3 sw.js
Cache name `sds-<VERSION>-<hash of the file list>`; precache list injected at export time (`__PRECACHE__`); offline fallback `offline.html` for navigations; cache-first for precached assets with network fallback; old caches deleted on activate; `skipWaiting` ONLY on message `{type:'SKIP_WAITING'}` (update after user click). A test proves the precache list equals the files actually present in `dist/`.
### 6.4 export-page.js
`node swarm/tools/export-page.js <projectDir> [--out dir] [--title t] [--brand forest-gold] [--langs en,zh-Hans,ms]` produces `dist/` with index.html (shell + sections), manifest, sw.js, offline.html, icons, assets (images, existing prefix table `/gjh/`, `/gjh-v11/` kept), design-system css/js, i18n catalogs, `version.json`. Keep every existing guarantee and test of the current exporter (single h1 check, unresolved reference report, image prefix table). Add the `--no-pwa` flag to keep the old single-file behaviour.

## 7. Lint ratchet (owner F): `swarm/tools/check-sections.js`
New rule ids (error unless stated): `raw-color` (hex/rgb/hsl/named colour literal in section CSS or inline style, `transparent`/`currentColor`/`inherit` allowed), `raw-font-size` (px/rem/em literal; allow `clamp()`/`var()`), `raw-duration`, `raw-easing`, `raw-z-index`, `raw-spacing` (warn), `important` (>0 is an error now), `no-i18n-text` (warn: visible text without `data-i18n`), `missing-alt`, `unscoped-selector` (existing), `redefine-sds-base` (a section CSS rule whose selector's last compound is a bare `.sds-*` base class without a section scope), `inline-large-data-uri` (existing), existing ids unchanged. A section may set tokens only by consuming `var(--sds-*)`; defining its own custom properties for colour is a `raw-color` finding.
Baseline: `swarm/design-system/ssot-baseline.json` maps `projectName -> ruleId -> count`; `node swarm/tools/check-sections.js <dir> --baseline` fails when any count rises above the baseline; `--update-baseline` rewrites it (only to lower counts, refuse to raise). Also `--ssot` verifies `build.js --check` (generated css in sync) and `i18n-extract --check` when a catalog exists. Every rule needs a unit test with a planted violation and a clean fixture.

`node --test swarm/test/*.test.js` passes; your own tests cover the happy path, a failure path and the edge cases named in your assignment; `node --check` on every JS file; no new dependencies; generated files are produced by tools, not hand-edited; English only; no git commands that change state.

## 10. Staffing, skills, tools and framework (so every Codex worker works like a trained specialist)
A worker is a staff member: it has a POSITION, a SKILL PACKAGE (handbook packs it must read), a TOOL KIT (commands it may run) and works inside the FRAMEWORK (SDS + contract + rounds). Nothing is left to improvisation.

### 10.1 Files
```
swarm/staff/
  staff.json             J   roster (schema below), the single source of truth for positions
  playbooks/<position-id>.md   J   one page per position: mission, inputs, outputs, definition of done, checklist, handoffs, escalation
  tools.md               J   tool kit: every command, when to use it, expected output, failure meaning
  handbook/              H, I  skill packs (each pack = one file, 60-140 lines, concrete rules + do/don't + a 5-item self-check)
    ui-ux-core.md  typography-layout.md  color-theme.md  accessibility.md          (H)
    motion-loader.md  i18n-content.md  pwa-performance.md  tokens-ssot.md  components-engineering.md  qa-verification.md   (I)
swarm/lib/staff.js       J   loader + prompt preamble builder (section 10.3)
swarm/test/staff.test.js J
```
At project init the server copies `swarm/staff/` and `swarm/design-system/` (css/js/json only) into `PROJECT/staff/` and `PROJECT/design-system/` so agents can read them inside their sandbox (the manager wires this; workers do not touch server.js).

### 10.3 lib/staff.js contract
```js
const staff = require('./staff');
staff.load(staffDir)                      // -> {positions, byId, byAgent(agentId)} ; validates schema, every skill has a handbook file, every tool exists in tools.md, every position has a playbook
staff.preamble({ staffDir, agentId, position, step })   // -> string <= 1400 chars, English:
  // "POSITION: <title>. MISSION: ... READ FIRST: staff/playbooks/<id>.md and handbook packs <list>. TOOLS you may run: <commands>. DEFINITION OF DONE: <3 bullets>. SDS RULES: use var(--sds-*), .sds-* components, data-i18n, data-reveal; no raw colours/sizes/durations."
staff.validate(staffDir)                  // -> {errors:[], warnings:[]}; CLI: node swarm/lib/staff.js --check
```
The manager will inject `preamble()` into every agent prompt in `lib/turns.js` and `server.js`; J only provides and tests it.

### 10.4 Tool kit (tools.md must document exactly these, with working commands)
`node swarm/design-system/build.js [--check]` (tokens), `node swarm/tools/check-sections.js <projectDir> [--baseline|--ssot|--json]` (lint ratchet), `node swarm/tools/i18n-extract.js <projectDir> [--write|--check]`, `node swarm/tools/export-page.js <projectDir> [--out]`, `node swarm/lib/staff.js --check`, `node --test swarm/test/*.test.js`, `node swarm/tools/contrast.js <fg> <bg>` (J adds this tiny WCAG contrast CLI and test: prints ratio and AA/AAA pass for normal and large text; accepts hex), the live preview URL pattern (`/p/dist/index.html`), and browser inspection through Chrome DevTools tools when the Codex environment offers them (state that it is optional and what to do when unavailable).

### 10.5 Framework statement (goes into the playbooks)
Order of authority: owner request > brief.md > direction.md and decisions.md > STANDARD.md and SDS_SPEC.md > handbook packs > personal taste. Ownership rule unchanged: edit only your own files. Parallel work protocol: read the channel, announce intent in one sentence, hand off through the channel with @mentions, never block waiting for a peer (assume the spec), verify with the tool kit before posting `done`.
